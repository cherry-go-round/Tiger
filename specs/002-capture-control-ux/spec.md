# 기능 명세: Capture Control UX

**Feature Branch**: `chore/kotlin-style-lint`

**작성일**: 2026-09-08

**상태**: 초안

**입력**: Session 목록에서 새 세션을 시작하고, 전체 화면 카메라 프리뷰에서 재생·일시 정지·정지 아이콘으로 Session과 Episode를 제어한다. 정지로 확정된 Session은 즉시 서버 전송을 시작하고 그 Session의 상세 화면으로 이동한다. 완료된 Session은 상세 화면에서도 전송 또는 재전송을 시작할 수 있다.

## 목표

수집자는 Session 목록에서 새 세션을 시작하고, 카메라 프리뷰가 중심인 전체 화면 작업 공간에서 익숙한 미디어 제어 아이콘만으로 수집을 조작한다. 사용자는 Episode라는 내부 데이터 단위를 별도로 조작할 필요 없이 재생, 일시 정지, 정지의 의미로 연속 수집과 작업 구간을 구분할 수 있어야 한다.

## 검증 범위

이 앱은 배포용 제품이 아닌 개발용 수집 앱이다. 2026-09-11 사용자 결정에 따라 TalkBack 실사용 접근성 검증은 필수 인수 조건에서 제외한다. 기존 아이콘 라벨·툴팁은 유지하고, 제어 상태·입력 차단·종료 확인 및 UI semantics는 자동 테스트로 검증한다.

## Clarifications

### Session 2026-09-08

- Q: 재생으로 시작하는 각 작업 구간의 `task`와 `object` 값은 어떻게 입력하나요? → A: 새 세션을 선택하면 카메라 프리뷰 위에 즉시 입력 모달을 표시해 공통 `task`와 `object`를 입력한다. 확인 전에는 재생을 노출하지 않으며, 입력한 값은 해당 Session의 모든 Episode에 적용한다.
- Q: Session을 정지해 확정한 뒤 어디로 이동해야 하나요? → A: 정지는 Session 확정 뒤 즉시 전송을 시작하고 업로드 상태를 보여주는 별도 화면으로 이동한다. Session 상세에서도 전송·재전송을 시작하면 같은 화면으로 이동하며, 상세 화면과 업로드 상태 화면은 분리한다. 업로드 상태 화면 이탈을 확인하면 진행 중인 전송을 즉시 중단하고, 강제 종료로 중단된 전송은 Session 상세에서 다시 시작한다.
- Q: 이미 외부 저장소에 있는 완료 Session은 앱 업데이트 후 어떻게 처리해야 하나요? → A: 기존 로컬 Session은 지원하지 않고 목록에서 제외한다. 내부 저장소로 이전하거나 기존 파일을 자동 삭제하지 않는다.
- Q: 목록과 상세의 Episode 개수에는 취소되거나 유효하지 않은 작업 구간도 포함하나요? → A: `CANCELLED` Episode 상태를 제거하고, 목록과 상세에는 정상 완료된 Episode 개수만 표시한다.
- Q: 업로드 상태 화면을 유지한 채 홈 화면으로 앱을 백그라운드로 보내면 전송을 계속해야 하나요? → A: 백그라운드 전환은 업로드 상태 화면 이탈로 보고 전송을 즉시 중단한다. 홈 화면 전환은 확인 알림을 표시할 수 없으므로, 뒤로 가기·닫기와 달리 확인 없이 중단한다.

### Session 2026-09-18

- Q: 별도 업로드 상태 화면을 유지해야 하나요? → A: 없앤다. 마감이 끝나면 Session은 저장되어 존재하므로 전송 진행과 결과는 그 Session의 상세에서 보여 준다. 마감은 짧고 벗어날 수 없어 작업 공간에서 막지만, 전송은 네트워크에 매여 길어질 수 있어 사용자를 붙잡아 두지 않는다. 2026-09-08의 "상세 화면과 업로드 상태 화면은 분리한다"를 대체한다.
- Q: 그러면 전송 취소는 어떻게 하나요? → A: 사용자가 중간에 끊는 수단을 두지 않는다. 상세는 둘러보는 화면이라 거기서 벗어나는 것을 중단 의사로 읽으면 사고가 된다. 실패하면 상세에 사유와 재전송이 함께 있어 막히지 않는다. 백그라운드 전환 시 취소는 유지하되 판정 기준을 "업로드 화면에 있는가"에서 "전송이 진행 중인가"로 바꾼다.
- Q: 수집한 Session을 삭제할 수 있어야 하나요? 삭제하면 서버에 업로드된 데이터는 어떻게 되나요? → A: 기기에서만 삭제한다. 서버에 DELETE API가 없으므로 이미 업로드된 데이터는 서버에서 삭제되지 않는다. 삭제는 기기 저장 공간을 비우는 동작이지 업로드를 취소하는 동작이 아니며, 확인 문구가 업로드 여부에 따라 결과가 다름을 말한다.
- Q: 목록에서도 바로 삭제할 수 있어야 하나요? 진입점을 어떻게 두나요? → A: Task Session 목록의 카드를 길게 눌러 연다. 카드마다 삭제 표를 상주시키지 않는다. 목록의 주 동작은 여는 것이고, 모든 행에 부수 동작이 붙으면 목록이 표로 얼룩진다. 동작이 하나뿐이라 메뉴 버튼을 세울 이유도 없다. 목록 카드에 세션 정보는 두지 않는다. 카드가 이미 시각·상태·Object·Episode 수·ID를 보여 주므로 한 탭 거리에 있는 것을 복제하게 된다.
- Q: 밀어서 삭제는 왜 쓰지 않나요? → A: 그 제스처는 실행취소가 따라온다는 약속을 달고 다닌다. 여기서는 번들을 실제로 지우므로 되돌릴 수 없다. 확인 판을 붙이면 제스처의 약속을 깨고, 붙이지 않으면 스크롤 오조작이 그대로 영구 삭제가 된다.
- Q: 전송 중인 Session도 삭제할 수 있나요? → A: 삭제할 수 없다. 전송이 번들을 읽고 있는 동안 삭제하면 전송이 무엇을 읽는지 알 수 없게 된다. 전송을 끊는 수단은 두지 않기로 했으므로(FR-014c) 전송이 끝나거나 실패한 뒤에 삭제한다.
- Q: 마감 중 진행 표시는 어디에 두나요? → A: 작업 공간을 덮는 판에 둔다. 그 구간에는 어떤 제어도 받지 않으므로 제어와 같은 줄에 두면 누를 수 있는 것처럼 보인다. 판은 프리뷰가 비치도록 깔고, 마감에 실패하면 같은 판에 사유와 확인을 표시해 작업 공간에 머무른다.

### Session 2026-09-23

- Q: 작업 영역이 흐린 것은 autofocus가 못 잡아서인가요? → A: 아니다. ARCore의 기본 `FocusMode`가 `FIXED`이고 초점을 1.0 D(1 m)에 못 박는다. 초점은 이미 고정이었고 **고를 수 없던 것**이 문제였다. 그래서 초점에 필요한 것은 "자동을 끄는 것"이 아니라 "값을 고르게 하는 것"이다.
- Q: 그러면 노출·ISO·화이트 밸런스도 같은 문제인가요? → A: 반대다. 그 셋은 고정이 아니라 매 프레임 움직이고 있었다. 실기기에서 10초를 찍으면 설정이 74번 바뀌고, 0.5초 만에 ISO가 50에서 1218로 올라간다. 초점은 고르는 것이, 나머지는 지키는 것이 모자랐다. 둘 중 하나만으로는 이 기능이 성립하지 않는다.
- Q: 값을 고르면 그대로 녹화되나요? → A: 그냥은 안 된다. ARCore가 `Session.resume()`에서 repeating request를 자기 것으로 갈아 끼우므로, resume 전에 건 수동 값은 한 프레임만 살아남고 그다음부터 자동으로 돌아간다. 요청이 바뀐 것을 알아채면 되받아야 하며, 되받은 뒤로는 ARCore가 다시 가져가지 않는다. 이 되받기 없이는 프리뷰에만 적용되고 `main_rgb.mp4`는 자동으로 찍히는 상태가 된다.
- Q: 화이트 밸런스는 `CONTROL_AWB_LOCK`으로 고정하면 되지 않나요? → A: 안 된다. lock은 절대값이 아니라 "지금 수렴한 값을 유지"라는 상대 상태다. 프리뷰의 `CameraDevice`를 닫고 ARCore가 새 session을 열면 AWB가 처음부터 다시 수렴하므로, 프리뷰에서 잠근 색이 녹화본으로 넘어가지 않는다. 프리뷰가 수렴시킨 gain과 transform을 숫자로 들고 건너간다. Kelvin이나 RGB gain을 직접 고르는 화면은 만들지 않는다. 목적이 정확한 색을 지정하는 것이 아니라 촬영 사이에 색이 변하지 않게 하는 것이기 때문이다.
- Q: 값의 범위는 어느 카메라에서 읽나요? → A: 프리뷰가 여는 첫 후면 카메라가 아니라 ARCore가 실제로 녹화에 쓰는 카메라다. 논리 카메라가 여럿인 기기에서는 ISO·노출 범위가 다르고, 어긋나면 조용히 다른 값으로 찍힌다. 영상만 봐서는 보이지 않는 어긋남이다.
- Q: 요청한 값과 실제 값이 다를 수 있나요? → A: 다르다. 센서가 노출과 프레임 간격을 µs로 양자화하고, 초점도 렌즈 스텝 해상도만큼 어긋난다. 그래서 metadata에 둘을 나눠 적는다. calibration은 실제로 쓰인 값 위에서만 뜻이 있다.

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - Session 목록에서 새 세션 시작 (우선순위: P1)

수집자는 홈에서 Task 이름 목록을 확인하고, 하나를 선택해 해당 Task의 Session을 수집 시각과 짧은 식별자로 확인한다. 그 뒤 새 세션을 선택해 카메라 프리뷰가 있는 전체 화면 수집 작업 공간으로 진입한다.

**우선순위 근거**: 수집 시작점과 기존 데이터 관리를 분리해야 사용자가 현재 작업 대상과 수집 상태를 혼동하지 않는다.

**독립 테스트**: 로컬 보관·전송 완료·전송 실패 상태와 서로 다른 Episode 개수를 가진 Session 목록에서 각 요약을 확인하고, 새 세션을 선택해 전체 화면 작업 공간과 시작 가능한 프리뷰 상태를 확인한다.

**인수 시나리오**:

1. **Given** Task 홈 화면, **When** 수집자가 Task를 선택하면, **Then** 해당 Task의 Session 목록이 열리고 각 항목은 수집 시각과 짧은 식별자로 구분된다.
2. **Given** Task 홈 화면, **When** 수집자가 새 세션을 선택하면, **Then** 전체 화면 수집 작업 공간이 열리고 홈 조작은 노출되지 않는다.
3. **Given** 수집 작업 공간, **When** 수집자가 화면을 보면, **Then** 전체 화면 카메라 프리뷰 위에 공통 `task`·`object` 입력 모달을 즉시 확인할 수 있으며 두 값을 입력한 뒤 첫 재생을 시작할 수 있다.
4. **Given** 카메라 또는 수집 준비가 불가능한 작업 공간, **When** 수집자가 진입하면, **Then** 원인과 다음 행동을 알 수 있으며 재생 조작은 시작되지 않는다.
5. **Given** 완료된 Session이 있는 Task 목록, **When** 수집자가 해당 항목을 선택하면, **Then** 수집 작업 공간이 아닌 해당 Session의 상세 화면으로 이동한다.

### 사용자 스토리 2 - 아이콘으로 연속 수집과 Episode 구간 제어 (우선순위: P1)

수집자는 텍스트 버튼 대신 카메라 프리뷰 우측 가장자리에 오버레이된 재생, 일시 정지, 정지 아이콘을 사용해 수집을 시작하고, 작업 구간을 나누며, 전체 Session을 끝낸다.

**우선순위 근거**: 수집 중에는 카메라 프리뷰와 현재 상태를 빠르게 인지하고 한 손으로 조작할 수 있어야 한다.

**독립 테스트**: 준비된 수집 화면에서 재생, 일시 정지, 재생, 정지 순서로 조작하고 Session 및 두 Episode의 시간 경계를 확인한다.

**인수 시나리오**:

1. **Given** 준비된 수집 화면, **When** 수집자가 재생 아이콘을 누르면, **Then** 새 Session 수집과 첫 작업 구간이 함께 시작되고 화면은 수집 중 상태가 된다.
2. **Given** 작업 구간이 진행 중인 수집 화면, **When** 수집자가 일시 정지 아이콘을 누르면, **Then** 현재 작업 구간만 종료되고 Session의 카메라·센서 수집은 계속된다.
3. **Given** 작업 구간이 종료됐지만 Session 수집은 계속되는 화면, **When** 수집자가 재생 아이콘을 누르면, **Then** 다음 작업 구간이 시작된다.
4. **Given** 수집 중인 화면, **When** 수집자가 정지 아이콘을 누르면, **Then** 열린 작업 구간을 종료하고 Session 수집을 종료·확정한 뒤 해당 Session의 서버 전송을 시작한다.
5. **Given** 정지로 마감이 시작된 수집 화면, **When** 마감이 진행되는 동안, **Then** 프리뷰가 비치는 판이 작업 공간을 덮고 진행 표시와 안내 문구를 보여 주며 제어를 받지 않는다.
6. **Given** 마감이 끝난 Session, **When** 수집자가 확정 결과를 확인하면, **Then** 방금 확정한 Session의 상세로 이동하고 그 화면에서 전송 진행을 확인한다.
7. **Given** 마감에 실패한 수집 화면, **When** 수집자가 결과를 확인하면, **Then** 덮은 판에 실패 사유와 확인이 표시되고, 확인하면 작업 공간에 머물러 바로 다시 수집할 수 있다.

### 사용자 스토리 3 - 제어 상태로 수집 흐름 인지 (우선순위: P2)

수집자는 카메라 프리뷰를 가리지 않는 제어 아이콘의 활성 상태와 필요한 일회성 안내를 통해 다음 조작을 알 수 있고, 실수로 수집을 종료하지 않는다.

**우선순위 근거**: 수집 중단 또는 구간 누락은 이후 데이터의 활용성을 떨어뜨린다.

**독립 테스트**: 준비, 작업 구간 진행, 작업 구간 종료 후 Session 유지, Session 확정 중의 화면을 비교해 각 상태에서 가능한 조작과 일회성 안내를 확인한다.

**인수 시나리오**:

1. **Given** 수집 화면의 모든 상태, **When** 수집자가 제어 영역을 보면, **Then** 활성화된 재생·일시 정지·정지 아이콘과 비활성 상태를 통해 다음 가능한 조작을 알 수 있다.
2. **Given** 준비 실패 또는 확정 중인 수집 화면, **When** 상태가 바뀌거나 조작이 제한되면, **Then** 필요한 이유 또는 진행 상황을 일회성 안내나 진행 표시로 알 수 있다.
3. **Given** 작업 구간 진행 중, **When** 수집자가 정지 아이콘을 누르면, **Then** 전체 수집 종료임을 확인할 기회가 제공된다.
4. **Given** 수집 작업 공간, **When** 수집자가 시스템 뒤로 가기 또는 전체 화면 sheet 우측 상단의 X 닫기를 시도하면, **Then** 녹화 중에는 Session 종료·완료·전송 시작 결과를 알리는 확인 절차가 제공되고, 녹화 전에는 Session을 만들지 않고 목록으로 돌아간다.

### 사용자 스토리 4 - Session 상세에서 전송 시작 (우선순위: P2)

수집자는 완료된 Session의 수집 요약, 로컬 원본 동영상과 Episode 개수를 확인하고 필요할 때 서버로 전송하거나 실패한 전송을 재시도한다. Detail의 동영상은 전체 화면 재생으로 확장할 수 있다. Detail은 화면 좌측 상단의 뒤로가기 아이콘으로 이전 맥락으로 돌아간다. 전송의 진행과 결과도 같은 Detail에서 확인한다.

**우선순위 근거**: 수집과 서버 전송을 분리하면 현장에서 수집 흐름을 방해하지 않으면서도 각 데이터의 전달 여부를 확인할 수 있다.

**독립 테스트**: 로컬 보관 상태와 전송 실패 상태의 완료 Session을 상세 화면에서 열어 각각 전송과 재전송을 실행하고, 같은 화면에서 결과 상태를 확인한다.

**인수 시나리오**:

1. **Given** 완료된 Session의 목록 항목, **When** 수집자가 항목을 선택하면, **Then** 상세 화면 본문에서 수집 일시, Task와 수집 대상 Object, 짧은 식별자, 수집 데이터 상태와 로컬 원본 동영상을 확인하고 전체 화면 재생으로 확장할 수 있다.
1a. **Given** Session 상세, **When** 수집자가 세션 정보를 열면, **Then** 전체 식별자, 수집 시각, Episode 개수, 수집 길이, 영상 해상도를 확인할 수 있다.
1c. **Given** Episode를 하나도 시작하지 않고 종료한 Session, **When** 수집자가 목록과 상세를 보면, **Then** 수집 시작 때 입력한 Task와 Object가 그대로 남아 있다.
1d. **Given** 방금 수집을 마감해 상세 화면으로 넘어온 Session, **When** 수집자가 화면을 보면, **Then** 메뉴를 열지 않고 본문에서 Task와 수집 대상 Object를 확인할 수 있다.
1b. **Given** 서로 다른 해상도로 수집한 Session, **When** 수집자가 각각의 세션 정보를 열면, **Then** 저장된 영상의 실제 해상도가 재생기가 보여 주는 크기와 같게 표시된다. 영상을 읽지 못하면 해상도만 알 수 없음으로 표시되고 나머지 항목은 정상 표시된다.
2. **Given** 아직 서버로 전송하지 않은 완료 Session, **When** 수집자가 상세 화면에서 전송을 선택하면, **Then** 해당 Session 전체의 전송이 시작되고 같은 화면의 상태가 전송 중으로 바뀐다.
3. **Given** 전송에 실패한 완료 Session, **When** 수집자가 상세 화면에서 재전송을 선택하면, **Then** 동일한 Session을 다시 전송하고 같은 화면에 머무른다.
4. **Given** 전송 중 또는 전송이 완료된 Session, **When** 수집자가 상세 화면을 보면, **Then** 해당 Session의 진행 또는 완료 결과를 확인할 수 있다. 아직 전송하지 않은 상태는 전송 행동이 대신 말하므로 따로 적지 않는다.
5. **Given** 전송 중인 Session 상세, **When** 수집자가 뒤로 가기를 누르면, **Then** 확인 없이 이전 화면으로 돌아가고 전송은 계속된다.
6. **Given** 전송 중인 Session, **When** 사용자가 앱을 백그라운드로 전환하면, **Then** 어느 화면에 있든 전송은 즉시 중단되고 해당 Session은 상세 화면에서 재전송할 수 있는 상태로 남는다.
7. **Given** 전송에 실패한 Session 상세, **When** 수집자가 화면을 보면, **Then** 실패 사유와 재전송 행동을 함께 확인할 수 있다.
8. **Given** 아직 전송하지 않은 완료 Session 상세, **When** 수집자가 삭제를 선택하면, **Then** 삭제하면 수집한 데이터를 복구할 수 없다는 확인을 거친 뒤에만 삭제되고, 확인하면 이전 화면으로 돌아가며 해당 Session은 목록에서 사라진다.
9. **Given** 전송이 완료된 Session 상세, **When** 수집자가 삭제를 선택하면, **Then** 기기에서만 삭제되며 서버에 업로드된 데이터는 삭제되지 않는다는 확인을 거친 뒤에만 삭제된다.
10. **Given** 전송 중인 Session 상세, **When** 수집자가 화면을 보면, **Then** 삭제 행동은 누를 수 없는 상태로 보인다.
11. **Given** Task Session 목록, **When** 수집자가 Session 카드를 길게 누르면, **Then** 삭제 행동이 누른 자리에서 열리고, 상세와 같은 확인을 거친 뒤에만 삭제되며, 확인하면 목록에 머무른 채 그 카드만 사라진다.
12. **Given** 한 Task의 마지막 Session, **When** 수집자가 목록에서 그 Session을 삭제하면, **Then** 빈 목록 안내가 표시되고 새 세션을 눌러 추가할 수 있음을 알 수 있다.

### 엣지 케이스

- 수집 준비 중 카메라 권한, AR 추적 또는 저장소 조건이 충족되지 않으면 재생 아이콘은 수집을 시작하지 않으며 필요한 조치를 안내한다.
- Session 확정 중에는 중복 입력으로 새 작업 구간이나 두 번째 종료가 시작되지 않는다.
- 작업 구간이 없는 상태에서 정지하면 Session은 정상 종료할 수 있다.
- 수집 중 화면이 예기치 않게 중단되면, 사용자는 다음 진입 시 해당 Session이 완료되지 않았음을 식별할 수 있다.
- 목록에 Session이 없을 때는 빈 상태와 새 세션 시작 행동을 함께 제공한다.
- 앱 삭제 또는 앱 데이터 삭제로 내부 보관 데이터가 함께 사라질 수 있으므로, 사용자는 보존이 필요한 Session을 전송해야 한다. (2026-09-22 내보내기 제거 후 갱신)
- 이전 버전의 외부 저장소에 보관된 완료 Session은 이 기능에서 목록·상세·전송 대상으로 지원하지 않으며 자동 이전 또는 자동 삭제하지 않는다. 삭제 행동도 이 Session의 파일에는 미치지 않는다.
- 삭제 도중 번들 디렉터리를 지우지 못해도 색인과 번들이 엇갈리지 않는다. 색인을 먼저 지우므로 남는 것은 목록에 보이지 않는 디렉터리뿐이며, 다음 실행이 회수한다.
- 삭제한 Session은 중단된 수집의 구제 경로로 되살아나지 않는다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 홈 화면에서 완료 Session을 공통 Task 이름별로 그룹화해 표시해야 한다. Task를 선택한 목록에서 각 Session은 수집 시각과 짧은 식별자로 구분하며, 숫자 Session 제목을 주 식별자로 표시해서는 안 된다.
- **FR-001a**: 시스템은 Task 목록의 완료 Session을 선택하면 해당 Session의 상세 화면으로 이동해야 하며, 완료된 Session을 수집 작업 공간으로 다시 열어서는 안 된다.
- **FR-002**: 시스템은 새 세션을 선택하면 카메라 프리뷰 중심의 전체 화면 sheet 수집 작업 공간을 열고, 우측 상단에 X 닫기 수단을 제공해야 한다.
- **FR-002a**: 시스템은 수집 작업 공간에서 카메라 프리뷰가 보이는 즉시 공통 `task`와 `object` 입력 모달을 표시하고, 두 값이 확인될 때까지 첫 재생을 노출하거나 시작하지 않아야 한다. 입력한 값은 해당 Session의 모든 Episode에 적용해야 한다.
- **FR-003**: 시스템은 준비 상태에서 재생 아이콘으로 새 Session과 첫 작업 구간을 함께 시작해야 한다.
- **FR-004**: 시스템은 작업 구간 진행 중 재생·일시 정지·정지의 표준 시각 아이콘을 화면 우측 가장자리의 세로 중앙에 세로로 쌓아 오버레이해 사용해야 하며, 텍스트 버튼이나 중복 재생 제어를 주 제어 수단으로 사용하지 않아야 한다. (2026-09-23) 폰을 가로로 물리는 거치대 집게가 화면 가운데를 가리므로 하단 중앙에서 옮겼다. 화면에는 폰의 가운데를 맞추는 세로 기준선을 함께 둔다.
- **FR-005**: 시스템은 일시 정지 아이콘을 누르면 현재 작업 구간만 종료하고 Session의 연속 원시 데이터 수집은 유지해야 한다.
- **FR-006**: 시스템은 작업 구간이 없는 수집 상태에서 재생 아이콘을 누르면 다음 작업 구간을 시작해야 한다.
- **FR-007**: 시스템은 정지 아이콘을 누르면 전체 Session을 종료·확정하고, 열린 작업 구간이 있으면 함께 종료한 뒤 해당 Session의 서버 전송을 시작해야 한다.
- **FR-008**: 시스템은 준비·작업 구간 진행·작업 구간 종료 후 Session 수집 유지·확정 중 상태마다 가능한 제어 아이콘을 활성 또는 비활성으로 구분해야 한다.
- **FR-008a**: 시스템은 준비 실패, 조작 제한, 확정 진행처럼 사용자가 즉시 알아야 하는 상태 변화에만 일회성 안내 또는 진행 표시를 제공해야 하며, 작업 구간 상태를 설명하는 상시 텍스트나 색상 표시는 요구하지 않는다.
- **FR-009**: 시스템은 정지, 시스템 뒤로 가기, 전체 화면 sheet의 X 닫기처럼 Session을 끝낼 수 있는 행동 전에 사용자가 결과를 확인할 기회를 제공해야 한다. 녹화 중 X 닫기 확인은 Session을 종료·완료하고 전송을 시작함을 명시해야 한다.
- **FR-010**: 시스템은 아이콘만 보이는 조작에도 보조 기술과 도구 설명에서 동작 의미를 전달해야 한다.
- **FR-011**: 시스템은 Session 확정이 끝나면 방금 확정한 Session의 상세 화면으로 이동하게 해야 한다.
- **FR-011a**: 시스템은 확정이 진행되는 동안 수집 작업 공간을 덮는 판에 진행 표시와 안내 문구를 제공해야 하며, 그 판 뒤로 프리뷰가 비쳐야 한다. 확정에 실패하면 같은 판에 사유와 확인을 표시하고 확인할 때까지 작업 공간에 머물러야 한다.
- **FR-012**: 시스템은 원시 Session bundle을 앱 전용 내부 저장 영역에 보관하고, Session 메타데이터와 상태만 별도로 관리해야 한다. 원시 bundle을 일반 파일 관리자가 직접 수정·삭제할 수 있는 위치에 보관해서는 안 된다.
- **FR-012a**: 시스템은 이전 버전의 외부 저장소에 보관된 Session bundle을 앱 전용 내부 저장 영역으로 자동 이전하거나 자동 삭제해서는 안 되며, 해당 Session을 새 목록·상세·전송 흐름에서 제외해야 한다.
- **FR-013**: 시스템은 Session 상세 화면 본문에서 로컬 원본 동영상 재생과 전체 화면 확장, 수집 일시, Task와 수집 대상 Object, 짧은 식별자, 수집 데이터 상태를 제공해야 한다. 어느 Session을 열어 두었는지는 본문이 답해야 하며, 화면 종류를 가리키는 제목으로 대신해서는 안 된다.
- **FR-013c**: 시스템은 Session을 특정해 주지 않는 값을 본문에서 덜어 내고 별도로 열어 보는 자리에 두어야 한다. 전체 식별자, 수집 시각, Episode 개수, 수집 길이, 영상 해상도가 여기 해당한다.
- **FR-013e**: 시스템은 수집 시작 때 입력받은 Task와 Object를 Session 색인에 저장해야 하며, Episode 행에서 역산해서는 안 된다. Episode를 하나도 시작하지 않고 끝난 Session도 두 이름을 유지해야 한다. 이전 버전에서 마감된 Session은 Episode 행이 가진 값으로 채워야 하며, 채울 값이 없는 Session만 이름 없는 Task로 남을 수 있다.
- **FR-013f**: 시스템은 Task Session 목록의 카드에 그 Session의 Object를, Session 상세 본문에 Task와 Object를 함께 표시해야 한다. 상세에서는 메뉴 뒤에 두어서는 안 된다. 수집을 마감한 직후에는 Task 묶음도 목록 카드도 지나오지 않고 상세로 오므로, 그 경로에서 두 이름이 화면에 한 번도 나오지 않게 된다. 카드에 Task를 함께 적지 않는 것은 그 화면의 이름표가 이미 Task이기 때문이다. 이름이 없는 쪽은 빈 자리를 세우지 않아야 하며, 둘 다 없으면 줄째로 빠져야 한다.
- **FR-013g**: 시스템은 Task와 Object를 수집 일시에 딸린 층으로 표시해야 하며, Episode 개수와 같은 층에 두어서는 안 된다. 그 층은 무엇을 찍은 것인지 알려 주지 않는 값의 자리이고, 두 이름은 그 화면에서 그것만 말한다.
- **FR-013h**: 시스템은 목록 카드와 Session 상세 본문에서 정해진 텍스트 역할 중에서 골라 써야 하며, 요소마다 글꼴·크기·굵기·색 조합을 새로 만들어서는 안 된다. 조합의 개수는 요소의 개수보다 적어야 하고, 성격이 같은 값은 한 역할을 함께 써야 한다. 두 화면에서 글꼴은 하나만 쓴다. 조합이 요소마다 다르면 어느 요소도 다른 요소와 스타일을 공유하지 않아 위계가 아니라 잡음으로 읽힌다.
- **FR-013i**: 시스템은 종류가 다른 값을 한 줄에 이어 붙여서는 안 되며, 값마다 제 자리를 주어야 한다. 부호로 잇는 것도 간격으로 벌리는 것도 답이 아니다. 목록 카드는 왼쪽에 수집에 대한 값(수집 일시·Object·Episode 개수)을, 오른쪽에 이 기록에 대한 값(식별자·전송 상태)을 둔다. 오른쪽 단의 값들은 한 크기로 두어야 한다. 크기가 다르면 두 값이 한 단으로 읽히지 않으며, 같은 크기라도 한글은 라틴 글자보다 em 상자를 꽉 채워 커 보이므로 왼쪽 단과 행이 어긋난 것처럼 보인다. 한 행에 크기가 다른 두 글자가 놓이면 baseline을 맞춰야 한다. 위를 맞추면 작은 글자가 떠 보인다.
- **FR-013j**: 시스템은 Session 식별자를 부수 정보로 다루어서는 안 된다. 이 앱에서 식별자는 서버에 올라간 수집분을 찾을 때 쓰는 주 수단이므로, 목록 카드에서는 수집 일시와 같은 행의 오른쪽 끝에 두어 훑는 눈이 먼저 닿게 하고, 크기는 낮추되 색을 옅게 하지 않아야 한다.
- **FR-013l**: 시스템은 목록·상세·세션 정보에서 글꼴을 하나만 써야 한다. 식별자에 고정폭을 쓰지 않는다. 글꼴이 둘이면 위계를 돕기보다 가린다.
- **FR-013k**: 시스템은 Session 상세 본문에서 목록 카드의 줄 수 제한을 따르지 않아도 되며, 이름표와 값을 층마다 한 줄씩 쌓아야 한다. 줄 수를 아끼는 규칙은 훑는 목록의 것이고 상세는 확인하는 화면이다. 이름과 그 아래 정보 사이는 줄 사이보다 넓고 다음 묶음보다는 좁게 띄워 두 묶음으로 갈라야 한다.
- **FR-013m**: 시스템은 세션 정보에서 값을 시트 제목보다 작게 두어야 한다. 값이 제목과 같은 크기이면 제목이 목록의 첫 항목처럼 읽히고 큰 글자가 사다리처럼 쌓인다. 값과 이름표의 크기 차이는 한 단계로 좁혀 두 줄이 한 묶음으로 붙게 하고, 행 사이는 값의 크기에 맞춰 좁혀야 한다. 전체 식별자가 한 줄에 들어가 행 높이가 고르게 유지되어야 한다.
- **FR-013d**: 시스템은 Session 상세에서 수집분의 영상 해상도를 확인할 수 있게 해야 한다. 값은 저장된 영상에서 직접 읽어 재생기가 보여 주는 크기와 같아야 하며, 이를 위해 Session 색인에 새 컬럼을 두어서는 안 된다. 영상을 읽지 못해도 상세 화면의 나머지 항목은 정상 표시해야 한다.
- **FR-013b**: 시스템은 Session 상세와 Task Session 목록의 상단에 좌측 뒤로가기 아이콘을 제공하고, 텍스트형 `목록으로` 버튼을 제공하지 않아야 한다. 바로 아래 본문이 같은 이름을 말하는 경우 상단에 제목을 두어 같은 말을 두 번 읽게 해서는 안 된다.
- **FR-013a**: 시스템은 `CANCELLED` Episode 상태를 사용하거나 사용자에게 Episode 취소 조작을 제공해서는 안 된다. 목록과 Session 상세의 Episode 개수는 정상 완료된 Episode만 집계해야 한다.
- **FR-014**: 시스템은 상세 화면에서 아직 전송하지 않은 완료 Session에는 전송 행동을, 전송 실패한 완료 Session에는 재전송 행동을 제공해야 한다. 전송을 시작해도 화면을 옮기지 않아야 한다.
- **FR-014a**: 시스템은 Session 상세에서 해당 Session의 전송 진행, 성공 또는 실패 상태를 표시해야 한다. 아직 전송하지 않은 상태는 전송 행동이 대신 말하므로 문구로 표시하지 않아야 한다. 전송 중 또는 전송 완료 상태에서는 중복 전송 행동을 제공해서는 안 된다.
- **FR-014b**: 시스템은 전송이 진행 중임을 Session 상세에서 알 수 있게 해야 한다. 서버에 진행을 묻지 않으므로 진행률을 표시하지 않는다.
- **FR-014b-1**: 시스템은 전송이 실패하면 Session 상세에 실패 사유와 재전송 행동을 함께 표시해야 한다. 사유에 따라 재전송 행동을 감추어서는 안 된다.
- **FR-014c**: 시스템은 사용자가 전송을 중간에 끊는 수단을 제공하지 않아야 하며, 전송 중에도 Session 상세를 벗어날 수 있어야 한다.
- **FR-014d**: 시스템은 전송 중 사용자가 앱을 백그라운드로 전환하면 확인 없이 전송을 즉시 중단하고, 해당 Session을 상세 화면에서 재전송할 수 있는 상태로 남겨야 한다.
- **FR-016**: 시스템은 Session 상세와 Task Session 목록에서 해당 Session을 기기에서 삭제하는 행동을 제공해야 한다. 삭제는 Session 단위로 번들 디렉터리와 색인을 함께 지우며, 서버에 이미 업로드된 데이터에는 미치지 않아야 한다.
- **FR-016e**: 시스템은 목록의 삭제 진입점을 카드에 상주하는 표로 두어서는 안 되며, 목록의 주 동작인 열기를 가려서도 안 된다. 밀어서 삭제하는 제스처를 사용해서는 안 된다. 실행취소를 제공하지 않으므로 오조작이 곧 영구 삭제가 된다.
- **FR-016f**: 시스템은 되돌릴 수 없는 동작의 확인 판을 같은 형태로 제공해야 한다. 세션 종료 확인과 세션 삭제 확인이 서로 다르게 보여서는 안 된다.
- **FR-016g**: 시스템은 목록이 비면 남은 공간에 안내를 제공하고, 무엇을 눌러 세션을 추가하는지 그 행동의 이름으로 알려야 한다. 마지막 세션을 삭제해 Task Session 목록이 빈 경우에도 같다.
- **FR-016a**: 시스템은 삭제 전에 확인을 받아야 하며, 확인 문구는 업로드 여부에 따라 결과가 다름을 말해야 한다. 아직 전송하지 않은 Session은 수집한 데이터를 복구할 수 없음을, 전송이 끝난 Session은 서버에 업로드된 데이터가 삭제되지 않음을 알려야 한다.
- **FR-016b**: 시스템은 전송이 진행 중인 Session의 삭제를 허용해서는 안 되며, 삭제 행동이 누를 수 없는 상태임을 보여야 한다.
- **FR-016c**: 시스템은 삭제 도중 번들 디렉터리를 지우지 못하더라도 재생·전송이 불가능한 Session이 목록에 남지 않게 해야 한다. 지우지 못한 디렉터리는 다음 실행에서 회수해야 한다.
- **FR-016d**: 시스템은 삭제한 Session이 중단된 수집의 구제 경로로 되살아나지 않게 해야 한다.
- **FR-017**: 시스템은 Session을 시작하기 전에 수집자가 초점·ISO·셔터를 프리뷰로 보면서 직접 정하고, 화이트 밸런스를 그 시점의 값으로 고정할 수 있게 해야 한다. 값을 바꾸면 프리뷰에 즉시 반영해야 한다. 수집자가 실제 작업 자세에서 필요한 영역이 식별되는 조건을 눈으로 찾는 것이 목적이므로, 확인 조작을 거쳐야 반영되는 방식이어서는 안 된다.
- **FR-017a**: 시스템은 프리뷰에서 정한 촬영 조건을 실제 녹화에 동일하게 적용해야 한다. 프리뷰에만 적용되고 녹화가 기기 자동 설정으로 돌아가서는 안 된다.
- **FR-017b**: 시스템은 Session이 시작된 뒤 촬영 조건 변경을 받아서는 안 되며, Session이 끝날 때까지 같은 값을 유지해야 한다. Session 중에는 촬영 조건 화면도 열지 않는다. 그 화면은 모달이라 열려 있는 동안 Session을 멈출 수 없다.
- **FR-017c**: 시스템은 선택 가능한 값의 범위를 실제 녹화에 사용되는 카메라가 보고한 범위로 제한해야 하며, 기기가 지원하지 않는 항목은 조작할 수 없게 하고 그 이유를 보여야 한다. 수동 제어를 지원하지 않는 기기에서 수집 자체를 막아서는 안 된다.
- **FR-017d**: 시스템은 목표 30 FPS를 유지해야 하며, 노출 시간이 프레임 간격을 넘는 조합을 선택할 수 없게 해야 한다.
- **FR-017e**: 시스템은 마지막으로 사용한 촬영 조건을 기억해 다음 실행의 기본값으로 제공해야 한다. calibration 촬영과 dataset 수집이 날짜를 달리해 진행되어도 같은 조건을 재현할 수 있어야 한다.
- **FR-017f**: 시스템은 그 Session에 요청한 촬영 조건과 센서가 실제로 사용한 값을 Session metadata에 함께 기록해야 한다. 요청값만으로 실제 촬영 조건을 단정해서는 안 된다.
- **FR-015**: 이 기능은 기존 Session·Episode 파일 형식과 서버 전송 계약을 유지해야 한다. 촬영 조건 기록은 metadata에 항목을 더하기만 하며, 그 항목이 없는 과거 Session도 계속 유효하다.

### 핵심 엔터티

- **Session**: 카메라, 센서, 자세 데이터를 연속으로 보관하는 하나의 수집 단위. 목록의 한 항목이며 정지로 종료·확정된다.
- **Episode**: Session 안에서 재생부터 일시 정지 또는 정지까지의 작업 구간. UI에서는 내부 용어로 전면 노출하지 않는다.
- **수집 작업 공간**: 카메라 프리뷰, 수집 상태, 시각 제어 아이콘을 제공하는 전체 화면 맥락이다.
- **Session 상세**: 완료된 Session의 수집 일시, 데이터 상태와 로컬 원본 동영상을 확인하고 전송 또는 재전송을 시작하거나 기기에서 삭제하는 화면이다. 세션 정보와 삭제는 화면의 주 동작이 아니므로 헤더 메뉴에 접어 둔다.
- **세션 정보**: Session을 특정해 주지 않는 값(전체 식별자, 수집 시각, Episode 개수, 수집 길이, 영상 해상도)을 상세 본문에서 덜어 내 따로 열어 보는 자리다.
- **촬영 조건**: 한 Session 내내 고정되는 초점·ISO·셔터·화이트 밸런스 한 벌이다. 수집자가 Session 시작 전에 프리뷰를 보며 정하고, 프리뷰와 녹화가 같은 값을 쓴다. Session 속성이므로 그 Session의 metadata에 요청값과 실제값을 함께 남긴다. 값을 고르는 것과 그 값이 변하지 않는 것이 함께 성립해야 calibration과 dataset을 같은 광학 조건으로 볼 수 있다.
- **Task**와 **Object**: 수집 시작 때 함께 입력받는 두 이름이다. 무슨 작업인지와 어떤 물체에 관한 작업인지를 가리키며, 한 Session의 모든 Episode에 같은 값으로 적용된다. Session 속성이므로 Session 색인에 저장한다. Task는 목록에서 Session을 묶는 키이고, Object는 그 묶음 안에서 Session을 가려 준다. 둘 다 Session을 특정해 주는 값이므로 세션 정보가 아니라 목록 카드와 상세 본문에 둔다.
## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 수집자는 Session 목록에서 세 번 이하의 직접 조작으로 수집 작업 공간을 열고 첫 작업 구간을 시작할 수 있다.
- **SC-002**: 준비, 작업 구간 진행, 작업 구간 종료 후 Session 수집 유지의 세 상태에서 사용자는 활성화된 제어 아이콘만 보고 다음 가능한 조작을 올바르게 구분할 수 있다.
- **SC-003**: 재생·일시 정지·정지 순서로 조작한 10회의 시험에서 Session 하나와 의도한 작업 구간 경계가 매번 하나씩 기록된다.
- **SC-004**: 수집 중 뒤로 가기 또는 종료 조작의 100%에서 의도치 않은 Session 종료 전 확인 기회가 제공된다.
- **SC-005**: 화면에 보이는 아이콘만으로도 보조 기술 사용자가 각 제어의 목적을 구분할 수 있다.
- **SC-006**: 완료된 Session을 목록에서 선택한 사용자는 한 번의 직접 조작으로 상세 화면을 열어 수집 데이터 상태를 확인하고, 한 번 더 조작해 Episode 개수와 영상 해상도를 확인할 수 있다.
- **SC-007**: 로컬 보관 또는 전송 실패 상태의 완료 Session은 상세 화면에서 각각 전송 또는 재전송을 시작하며, 진행과 결과를 같은 화면에서 확인할 수 있다. 전송 중·완료 상태에는 중복 전송 행동이 노출되지 않는다.
- **SC-008**: 전송 중 Session 상세를 벗어나도 전송은 이어지며, 백그라운드 전환으로 중단된 Session은 상세 화면에서 재전송할 수 있다.
- **SC-009**: 전송 중 앱을 백그라운드로 전환한 Session은 전송이 즉시 중단되고, 이후 상세 화면에서 재전송할 수 있다.
- **SC-010**: 삭제한 Session은 목록·색인·번들 디렉터리 세 곳에서 모두 사라지며, 앱을 다시 실행해도 목록에 돌아오지 않는다.
- **SC-011**: 삭제는 확인을 거치지 않고 일어나지 않는다. 확인 문구는 업로드 여부에 따라 사용자가 잃는 것이 무엇인지 다르게 말한다.
- **SC-012**: 전송이 진행 중인 Session은 상세와 목록 어느 쪽에서도 삭제 행동을 실행할 수 없다.

## 가정

- 기존에 정의된 Session, Episode, 라벨 및 데이터 무결성 규칙은 유지한다.
- 재생은 준비 상태에서는 새 Session과 첫 Episode를 시작하고, Episode가 종료된 수집 상태에서는 다음 Episode를 시작한다.
- 정지는 열린 Episode가 있으면 그 시점에 종료한 뒤 Session을 확정한다.
- 카메라 프리뷰는 수집자가 기기 방향과 관찰 대상을 확인하는 용도이며, Session에 보관되는 원본 영상 계약을 대체하지 않는다.
- 작업 구간 상태는 상시 텍스트나 색상으로 설명하지 않고, 제어 아이콘의 활성 상태로 전달한다. 준비 실패·확정 중처럼 즉시 안내가 필요한 경우에만 일회성 안내 또는 진행 표시를 사용한다.
- 원시 bundle은 앱 전용 내부 저장 영역에 보관하고, 데이터베이스는 Session의 메타데이터·상태·Episode 개수를 목록과 상세에 제공하는 색인으로만 사용한다.
- 이전 버전의 외부 저장소 bundle은 자동 이전·삭제하지 않고 새 목록·상세·전송 흐름에서 제외한다.
- 서버의 Session 목록·상세 조회나 서버 삭제 기능은 이번 범위에 포함하지 않는다. 기존 Session 전송 계약을 통해 전송과 재전송만 제공한다.
- 서버가 전송 중 진행률을 제공하지 않으므로 진행률을 표시하지 않는다.
- 사용자가 앱을 백그라운드로 전환하거나 앱이 강제 종료되면 전송은 중단되고 Session 상세에서 수동 재전송한다. 홈 화면 전환은 확인 알림을 표시할 수 없으므로 확인 없이 중단한다.
- 이번 범위는 수집 화면, Session 목록, Session 상세과 내부 저장 위치 변경이며, 내보내기와 서버 전송 프로토콜 자체의 변경은 포함하지 않는다.
