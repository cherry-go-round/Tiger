# Capture Control UI 계약
## 화면과 진입점
| 화면 | 진입 | 주요 행동 | 이탈 동작 |
| --- | --- | --- | --- |
| Task 홈 | 앱 시작 | Task 이름별 완료 Session 그룹 열기, 새 세션 시작 | 시스템 뒤로 가기로 앱 종료. 백스택의 뿌리이므로 돌아갈 화면이 없다 |
| Task Session 목록 | Task 홈의 Task 선택 | 수집 시각·Object·짧은 식별자로 구분된 완료 Session 열기, 카드를 길게 눌러 그 Session 삭제 | 좌측 상단 뒤로가기 아이콘 또는 시스템 뒤로 가기로 Task 홈 복귀 |
| 수집 작업 공간 | 새 세션 | 전체 화면 라이브 프리뷰 위 즉시 표시되는 task/object 입력 모달 확인, 하단 중앙 오버레이 재생·일시 정지·정지 | 다른 오버레이와 같은 배경 위의 흰색 X와 시스템 뒤로 가기. 녹화 중에는 Session 종료·완료·전송 시작 확인 필요, 녹화 전에는 목록으로 복귀 |
| Session Detail | Task Session 목록에서 완료 Session 선택, 수집 마감 | 영상 비율에 맞춘 영역에서 로컬 원본 동영상 재생, 플레이어 우측 하단 전체 화면 버튼으로 확장, 본문에서 수집 일시·Task·Object·짧은 식별자 확인, 우측 상단 메뉴에서 세션 정보 열기와 세션 삭제, 전송 진행과 종료 상태 확인, 전송 또는 재전송 시작 | 좌측 상단 뒤로가기 아이콘 또는 시스템 뒤로 가기로 직전 화면 복귀. 전송 중에도 막지 않는다 |
| 전체 화면 동영상 | Session Detail의 전체 화면 버튼 선택 | 검은 배경에서 원본 비율로 동영상 재생, 우측 상단 회전 버튼으로 가로 고정 켜고 끄기 | 좌측 상단 뒤로가기 아이콘, 시스템 뒤로 가기 또는 플레이어의 전체 화면 종료 버튼으로 Session Detail 복귀 |
## 화면 전환과 뒤로 가기
조회 흐름은 백스택을 가진다. 전환은 `NavHost`가 소유하고, 각 화면의 이탈은 목적지를 지정하지 않고
직전 화면으로 pop한다. 좌측 상단 뒤로가기 아이콘과 시스템 뒤로 가기는 같은 동작을 한다.
```text
수집 화면 root                    ARCore 런타임, previewSurface, 업로드 Job 보유
  NavHost                         조회 흐름
    Task 홈
    Task Session 목록
    Session Detail
    전체 화면 동영상
  수집 중이면 수집 작업 공간        모달 오버레이, NavHost 바깥
```
- 화면 인자(Task 이름, Session 식별자)는 type-safe route로 전달한다. Task 이름은 사용자 자유
  입력이므로 route 문자열을 직접 조립하지 않는다.
- 이탈 대상을 하드코딩하지 않는다. Session Detail은 진입 경로가 Task Session 목록이든 수집 마감이든
  자신이 들어온 화면으로 돌아간다.
- 수집 작업 공간은 목적지가 아니다. 진입 경로가 하나뿐이고, 뒤로 가기가 이전 화면 복귀가 아니라
  종료 확인이며, 안에 준비 입력 모달을 품는다. 백스택 pop이 아닌 해제 가드다.
- 전송은 목적지를 갖지 않는다. 마감이 끝나면 Session은 저장되어 존재하므로, 전송 진행과 결과는 그
  Session의 Detail에서 보여 준다. 전송은 네트워크에 매여 길어질 수 있어 사용자를 붙잡아 두지 않는다.
- Task 홈에서 뒤로 가기를 누르면 앱이 종료된다.
- 프로세스가 재생성되면 조회 흐름의 백스택을 복원한다. 수집 작업 공간은 복원하지 않는다. 백그라운드
  전환 시 진행 중인 Session을 `INTERRUPTED`로 마감하므로 되살릴 수집 상태가 없다.
## 수집 제어
| 상태 | 활성 제어 | 이벤트 |
| --- | --- | --- |
| 유효한 task/object가 입력된 준비 상태 | 재생 | Session과 첫 Episode 생성 |
| Episode 진행 중 | 일시 정지, 정지 | 일시 정지는 Episode 완료, 정지는 Episode 완료·Session 확정·업로드 시작 |
| Episode 없음, Session 수집 중 | 재생, 정지 | 재생은 다음 Episode 시작, 정지는 확정·업로드 시작 |
| 확정 중 | 없음 | 마감이 끝날 때까지 중복 제어 무시 |
제어 아이콘은 프리뷰 하단 중앙에만 표시하며, 준비 상태에는 재생 하나, Episode 진행 중에는 일시 정지와 정지, Episode 없음 상태에는 재생과 정지를 표시한다. X 닫기는 화면 우측 상단에 다른 오버레이와 같은 배경을 깔고 흰색 굵은 글리프로 표시한다. 모든 제어 아이콘과 X 닫기에는 접근성 라벨과 툴팁을 제공한다. task와 object는 프리뷰가 보이는 즉시 표시되는 준비 입력 모달이다.
상단 오버레이는 상태 배지·해상도 배지와 X 닫기를 한 행에 담아 좌우 끝에 배치한다. 기준은 프리뷰가 아니라 화면이며, 시스템 영역을 침범하지 않는다. 배지가 길어져도 X 닫기 자리를 침범하지 않으므로 화면 비율과 무관하게 두 요소는 겹치지 않는다. 프리뷰가 16:9로 고정되어 생기는 검은 띠 위에 상단 오버레이가 얹힐 수 있다. 오버레이 배경은 뒤에 무엇이 오든 같은 밝기로 읽혀야 한다. 반투명 검정은 검은 띠 위에서 사라져 배지가 잘린 것처럼 보이므로, 순검정이 아닌 중성 회색을 거의 불투명하게 쓴다. 상태 배지와 해상도 배지, 제어 아이콘, X 닫기가 모두 같은 배경을 쓴다.
제어 아이콘은 색으로 의미를 구분한다. 재생은 강조색, 일시 정지는 흰색, 정지는 붉은색으로 표시한다. 정지는 Session을 확정하고 전송을 시작하는 되돌릴 수 없는 동작이므로 같은 자리의 다른 아이콘과 색이 달라야 한다. 종료 확인 대화상자도 같은 위계를 따라 확인은 error 색 버튼, 취소는 text 버튼으로 표시한다. 비활성 제어는 의미색을 지우고 중성 흰색 38%로 표시한다. 의미색을 흐리기만 하면 여전히 그 색으로 읽혀 비활성으로 보이지 않는다.
첫 재생 전에는 권한·AR·camera 준비로 라이브 프리뷰만 실행한다. 프리뷰 실패 시 다음 행동을 안내하고 재생을 막으며, Session이나 원시 bundle을 만들면 안 된다.
### Phase 5 제어 안전성
- 첫 프리뷰 프레임과 유효한 Task/Object가 준비되기 전에는 재생을 비활성화한다. 준비 실패 안내는 한 번 표시하며, 권한을 허용하거나 작업 공간을 다시 열도록 안내한다.
- 시작·Episode 저장·확정 작업을 시작하는 콜백에서 즉시 입력을 잠근다. 비동기 작업이 끝날 때까지 재생·일시 정지·정지·닫기와 시스템 뒤로 가기를 차단한다.
- 확정 중에는 작업 공간을 덮는 판에 접근성 이름이 있는 진행 표시와 안내 문구를 둔다. 그 구간에는 어떤 제어도 받지 않으므로, 제어와 같은 줄에 진행 표시를 두어 누를 수 있는 것처럼 보이게 하지 않는다. 판은 프리뷰가 비치도록 깔고, 그 위 문구는 장면이 가장 밝을 때에도 WCAG AA를 넘는 명도로 표시한다.
- 마감에 실패하면 같은 판에 사유와 확인을 표시하고, 확인할 때까지 작업 공간에 머무른다. 저장된 Session이 없어 넘어갈 곳이 없으며, 프리뷰가 살아 있어야 바로 다시 찍을 수 있다.
- 정지·뒤로 가기·X는 같은 종료 확인 정책을 사용한다. 취소하면 수집을 유지하고 확인한 경우에만 확정한다. 녹화 전 뒤로 가기·X는 Session을 생성하지 않고 목록으로 돌아간다.
## 재생 동작
- 재생기는 Media3(ExoPlayer)의 `PlayerView`를 쓴다. 재생·일시 정지, seek bar, 경과·총 시간, 버퍼링 표시, 탭하면 나타났다 사라지는 컨트롤, 영상 비율 유지는 `PlayerView`가 제공하는 것을 그대로 쓴다.
- Session Detail과 전체 화면은 같은 재생기를 공유한다. 두 화면을 오갈 때 재생 위치가 유지되어야 한다.
- 앱은 세로로 고정한다. 수집 작업 공간만 가로로 고정하고, 나머지 화면은 기기를 눕혀도 돌지 않는다.
- 전체 화면은 진입만으로 방향을 바꾸지 않는다. 세로로 들고 있으면 레터박스로 보인다.
- 전체 화면 우측 상단의 회전 버튼을 누르면 가로로 고정하고, 다시 누르면 세로로 돌아온다. 가로로 보는 유일한 경로이며, 고정 상태는 버튼 배경으로 구분한다.
- 뒤로 가기와 회전 버튼은 플레이어 컨트롤과 같이 나타나고 같이 숨는다. 재생할 영상이 없으면 뒤로 가기는 계속 보인다.
- Session Detail의 재생 영역은 영상의 가로세로 비율을 따른다. 회전 metadata가 적용된 크기를 쓰므로 `video_rotation_degrees`가 90인 수집분은 세로 비율로 표시한다.
- 화면을 돌려도 Activity를 다시 만들지 않는다. manifest의 `configChanges`가 이를 보장한다.
## 조회 화면의 짜임
- 목록과 상세는 같은 짜임을 쓴다. 굵은 이름 아래 그것을 설명하는 한 줄이 붙고, 층을 가르는 것은
  이름의 크기다. 딸린 줄은 어느 층에서나 같은 크기로 둔다.
- 홈의 이름은 앱 이름이다. 그 화면의 카드는 Task이고 그 안이 Session이라, 어느 쪽을 제목으로 삼아도
  바로 아래 내용과 어긋난다. 홈에는 뒤로 갈 곳이 없으므로 상단 헤더도 두지 않는다.
- 헤더가 없는 화면은 헤더가 차지하는 높이만큼을 비운다. 헤더를 둔 화면은 본문을 헤더 아래에서
  시작하므로, 그만큼 비워야 화면을 오갈 때 이름표가 제자리에 머무르는 것으로 보인다. 본문 위
  여백은 두 화면이 같은 값을 쓴다.
- 이름을 헤더 제목의 높이에 맞추지 않는다. 맞출 상대가 없다. 어느 화면이든 이름은 본문의 이름표가
  말하고 헤더에는 뒤로 가기와 부수 동작만 남으므로, 헤더 제목은 어디에서도 렌더되지 않는다. 그
  정렬을 쓰던 동안 홈의 이름표는 다른 화면보다 50dp 위에 붙어 화면 위쪽에 눌린 것으로 보였다.
- 새 세션은 목록 화면의 유일한 주 동작이므로 FAB에 둔다. 헤더의 아이콘 버튼은 부수 동작 자리다.
  Task의 Session 목록에서 시작하면 그 화면이 이미 아는 Task 이름을 채운 채로 연다.
- 상세의 세션 정보와 세션 삭제는 상단 우측 메뉴 하나에 접는다. 둘 다 화면의 주 동작이 아니라
  확인하거나 정리하러 들어왔을 때만 찾는다. 제목이 없는 헤더에 흐린 글리프를 나란히 세우면 둘 다
  무엇인지 추측해야 하는 표가 되지만, 메뉴로 접으면 글자로 이름이 붙는다. 메뉴 버튼은 뒤로 가기와
  나란히 서도 같은 급의 동작이 아니므로 글리프를 더 작게 둔다. 항목에는 글자 앞에 글리프를 붙이고,
  글리프에는 접근성 이름을 두지 않는다. 바로 옆 글자가 이미 이름을 말하므로 두 번 읽게 된다.
- 목록 카드의 삭제는 길게 눌러 연다. 카드마다 삭제 표를 상주시키지 않는다. 목록의 주 동작은 여는
  것이고, 모든 행에 부수 동작이 붙으면 목록이 표로 얼룩진다. 동작이 하나뿐이라 메뉴 버튼을 세울
  이유도 없다. 목록 카드에 세션 정보는 두지 않는다. 카드가 이미 시각·상태·Object·ID를 보여 주므로
  한 탭 거리에 있는 것을 복제하게 된다.
- 두 이름은 목록 카드와 상세 본문에 놓고, 세션 정보에는 두지 않는다. 그 시트는 Session을 특정해
  주지 않는 값의 자리인데 둘은 고를 때 쓰는 값이다. 결정적인 것은 수집을 마감한 직후 경로다.
  그때는 Task 묶음도 목록 카드도 지나오지 않고 상세로 바로 오므로 두 이름이 화면에 한 번도 나온
  적이 없다. 방금 찍은 것이 맞는지 확인하는 자리에서 메뉴를 한 번 더 열게 할 수 없다.
- 카드에는 Object만, 상세 본문에는 Task와 Object를 함께 적는다. 카드는 Task 이름을 단 화면 안에
  있어 그 이름을 행마다 되풀이할 이유가 없지만, 상세는 스스로 말하지 않으면 알 길이 없고 Object만
  두면 이름의 절반이 된다. 둘은 한 다이얼로그에서 함께 입력받은 한 쌍이므로 한 줄에 둔다.
- 종류가 다른 값을 한 줄에 이어 붙이지 않는다. 값마다 제 자리를 준다. 서로 관계가 없는 두 값을 한
  줄에 몰면 무엇으로 이어도 어색한데, 부호나 간격이 아니라 관계가 없다는 것이 원인이다. 가운뎃점은
  한국어에서 같은 종류의 낱말을 묶는 부호라 다른 종류를 이으면 거짓말이 되고, 간격은 왜 붙어 있는지
  설명하지 않는다.
- 목록 카드에 Episode 개수를 두지 않는다. 목록에서 세션을 고를 때 쓰는 값은 수집 일시·식별자·전송
  상태이고 분량은 거기 들지 않는다. 자리를 주면 왼쪽 단이 3층이 되어, Object가 없는 세션에서는
  가운데가 빈 줄로 남아 시각과 개수 사이가 벌어졌다. 분량은 한 탭 거리의 세션 정보가 말한다.
- 묶고 싶은 것을 붙여 놓는다. 붙여 놓은 것이 곧 묶인 것으로 읽히므로, 자리가 종류를 거스르면 자리가
  이긴다. 목록 카드가 열로 종류를 가르던 동안 식별자와 전송 상태가 같은 오른쪽 기둥에 세로로 붙어
  한 묶음으로 보였는데, 앞은 메타이고 뒤는 상태다. 행으로 갈라도 마찬가지였다.
- 그래서 카드는 이렇게 둔다. 첫 행 왼쪽에 이름(수집 일시), 같은 행 오른쪽 끝에 상태(전송 상태),
  그 아래로 메타(Object, 짧은 ID)를 세로로 쌓는다. 이름과 상태는 행의 양 끝이라 멀고, 메타 둘은
  서로의 바로 아래위에 있어 묶인다. 값을 부호로 이어 붙이지 않는다. 값마다 제 줄을 주고, 묶이는
  것은 서로 붙어 있다는 사실이 말한다.
- 상태가 첫 행에 오는 것은 그 행에서 변하는 유일한 값이기 때문이다. 목록을 훑는 이유가 무엇이
  올라갔고 무엇이 안 올라갔는지 보는 것이다. 메타는 변하지 않으므로 아래 행에서 기다려도 된다.
- 잉크는 셋이다. 진한 잉크는 값과 이름, 옅은 잉크는 값에 딸린 값과 행 이름표, 가장 옅은 잉크는 값이
  아니라 값을 가리키는 것(묶음 이름표, 항목 개수, 기계가 부르는 이름)이다. 표지와 값이 같은 잉크를
  쓰면 표지가 값으로 읽힌다.
- 목록 카드에 이름표 낱말을 적지 않는다. `Object`와 `ID`는 카드마다 똑같이 되풀이되는 비계이고, 어느
  쪽이 무엇인지는 잉크의 단계가 가른다. Object는 한 단계 옅고 식별자는 두 단계 옅으며, 식별자 앞의
  `#`가 그것이 번호임을 한 글자로 말한다. 짧은 ID를 굵게 두지도 않는다. 목록에서 세션을 고를 때 쓰는
  값이 아니라 고른 뒤에 쓰는 값이다.
- 상세에서는 이름표를 적는다. 거기서는 값이 무엇인지 확인하러 들어온 것이고 한 번만 나오므로
  되풀이가 아니다.
- 화면의 이름은 제 층에 혼자 선다. 아래 값들보다 한 계단 반이 아니라 두 계단 크다. iOS 메모의 large
  title이 같은 자리이며, 그 크기가 "여기가 어디인가"를 묻지 않아도 답해 준다.
- 메뉴 항목의 색은 역할이 아니라 컴포넌트가 정한다. 되돌릴 수 없는 항목은 error 색, 누를 수 없는
  항목은 흐린 색으로 그려야 하는데 그 판단이 상태에 딸려 있기 때문이다. 글자에 색을 박아 두었을 때
  삭제 항목의 글리프만 붉고 글자는 검었고 비활성일 때 흐려지지도 않았다.
- 메뉴 항목의 글리프와 글자 사이는 항목의 가장자리 여백보다 좁다. 두 간격이 같으면 글리프가 글자에
  붙은 것이 아니라 여백 둘 사이에 떠 있는 것으로 읽힌다.
- 프리뷰 위의 글은 표면의 타입 스케일을 따르지 않는다. 뒤가 장면이라 배경 밝기가 바뀌고, 팔을 뻗은
  거리에서 곁눈으로 보며, 글자마다 제 배경을 이고 있다. 실기기에서 맞춘 값이므로 표면 스케일에
  맞추려고 옮기지 않는다. 대신 그 값이 자리마다 새로 생기지 않도록 역할에 이름을 붙여 묶어 둔다.
- 이름표와 값을 한 문자열로 이어 붙이지 않는다. `Task 문도`가 아니라 `Task`와 `문도`다. 문장이 아니라
  이름표와 그것이 가리키는 값이고 둘은 종류가 다르다. 붙여 쓰면 이름표가 값의 일부처럼 읽히고, 줄을
  여럿 쌓으면 어느 낱말이 이름표인지 매번 다시 가려내야 한다. 이름표 기둥은 폭을 고정해 값이 한
  기둥에 정렬되게 한다. 이름표는 값보다 옅되 크기는 같다. 크기까지 내리면 묶음 이름표와 같은 층이
  되어 어느 것이 무엇의 표지인지 흐려진다.
- 전송 상태가 첫 행의 오른쪽 끝에 온다. 그 행에서 변하는 유일한 값이고, 목록을 훑는 이유가 무엇이
  올라갔고 무엇이 안 올라갔는지 보는 것이기 때문이다. 메타는 변하지 않으므로 아래 행에서 기다려도
  된다.
- 성격이 다른 값이 상세에 쌓일 때는 묶음마다 이름표를 붙인다. 이 수집이 무엇인지 말하는 값들(`세션
  정보`)과 그 기록이 지금 어떤지 말하는 줄(`업로드 상태`)이다. 간격만으로 가르면 무엇이 왜 갈렸는지는
  말해 주지 못하고, 이름표가 없으면 전송 상태가 Task·Object·ID와 같은 종류의 값으로 읽힌다.
- 묶음은 이름표를 머리에 달고 내용을 카드에 담는다. Apple의 grouped list가 하는 그것이다. 이름표는
  카드 바깥 회색 바닥 위에 서고, 카드의 왼쪽 끝에 맞춘다. 카드 안 글자에 맞추면 한 칸 들여쓴 꼴이
  되어 화면 제목과 어긋난다. 카드의 안쪽 여백은 카드의 것이지 바깥에 선 글자가 따를 선이 아니다.
  화면 제목과 이름표와 카드의 왼쪽 끝이 한 줄에 서야 왼쪽 가장자리가 하나로 읽힌다.
- 카드 없이 이름표만 달지 않는다. 그러면 이름표의 크기가 어느 쪽으로도 맞지 않는다. 제목이라면 아래
  글보다 크고 굵어야 하는데 작고, 이름표라면 이름표답게 보여야 하는데 그냥 작은 한 줄이다. 원인은
  크기가 아니라 그릇이 없다는 것이다. grouped list에서 구획 머리가 작아도 되는 것은 묶는 일을 머리가
  아니라 카드가 하기 때문이고, 그릇 없이 머리만 달면 그 작은 글자가 묶는 일까지 혼자 해야 한다.
- 이름표를 키워 제목으로 만들지 않는다. 한 화면에 제목이 둘이 되고, 수집 일시가 화면의 이름이라는
  것이 흐려진다.
- 묶음 이름표는 caption 층의 진한 잉크다. 카드 안 글보다 두 칸 작고 굵기가 한 단계 높다. 옅게 두지
  않는다. 머리글이지 딸린 값이 아니다. 행 이름표와 같은 옅은 잉크를 쓰던 동안, 묶음 이름표가 행
  이름표의 작은 버전으로 읽혀 둘의 층이 갈리지 않았다.
- 세션 정보 시트의 이름은 `상세 정보`다. 상세 본문의 `세션 정보` 묶음과 이름이 겹치면 같은 것을 두
  군데서 보여 주는 것처럼 읽힌다. 시트는 그 묶음이 담지 않는 값(전체 ID·길이·해상도·Episode 수)의
  자리다.
- 줄상자가 글자를 감싸게 해서 쓴 간격이 곧 보이는 간격이 되게 한다. Material 3의 타입 스케일은 줄
  높이를 글자 크기보다 크게 잡고(16sp 글자에 24dp 줄상자) 그 차이가 상자 위아래 여백으로 남는다.
  `spacedBy`는 그 상자 바깥에 더해지므로, 카드에 4dp를 주고도 실제로는 13dp가 나왔다. 눈으로 맞춘
  숫자는 글꼴이나 타입 스케일이 바뀌는 순간 다시 어긋나므로, 상자를 깎아 두고 간격을 그 자리에서
  정한다. 프리뷰 위 알약 배지는 예외다. 거기서는 상자의 여백이 배지 안쪽 여백 노릇을 한다.
- 한 덩어리를 가르는 간격은 그 덩어리를 감싸는 여백보다 뚜렷하게 작다. 카드는 안쪽 여백 16dp에 두
  줄 사이 8dp로 절반이다. 세 간격이 엇비슷하면 무엇이 한 덩어리인지를 간격이 말해 주지 않아, 이름과
  그에 딸린 값이 따로 뜬다. 실제로 위·가운데·아래가 20 / 13 / 18dp였던 동안 카드가 그렇게 읽혔다.
- 스타일은 정해진 역할에서 고르고, 요소마다 조합을 새로 만들지 않는다. 두 화면이 쓰는 역할은
  여덟이다.
  | 역할 | 쓰는 곳 |
  |---|---|
  | `sectionName` | 한 묶음을 이끄는 이름 |
  | `itemName` | 수집 일시, 카드의 Task 이름, 화면 헤더 제목, 세션 정보 제목 |
  | `supporting` | 카드의 Object와 전송 상태, 세션 개수, 세션 정보의 이름표 |
  | `value` | 세션 정보의 값 |
  | `body` | 상세의 전송 상태 |
  | `bodyMuted` | 상세의 Task·Object·짧은 ID, 실패 사유, 빈 목록 안내 |
  | `groupLabel` | 상세의 묶음 이름표 |
  | `menuItem` | 메뉴 항목의 글자 |
  크기·굵기·색은 `ui/theme/TigerText.kt`가 역할마다 정의한다. 화면은 이름으로만 고르고 조합을 직접
  만들지 않는다. 각 역할이 왜 그 조합인지도 거기 적혀 있으므로 이 문서에 값을 옮겨 적지 않는다.
  조합이 요소마다 다르면 어느 요소도 다른 요소와 스타일을 공유하지 않아 위계가 아니라 잡음으로
  읽힌다. 값이 넷인 GitHub의 커밋 행은 조합 셋으로 끝내고 글꼴은 하나, 크기는 둘만 쓴다. 성격이
  같은 값은 한 역할을 함께 쓰는 것이 위계를 만드는 방법이다.
- 중성 계열은 앱이 고정하고 강조색만 기기 배경화면에서 받는다. `dynamicColor`가 파생하는 중성은
  배경화면의 색조를 물고 오는데, 화면의 대부분을 차지하는 판에서는 그것이 색으로 읽힌다. `SM-G973N`
  에서 바닥이 `#E8EFF6`으로 나와 파랑이 빨강보다 14 높았고, 회색으로 깐 판이 푸른 판으로 보였다.
  Android 12는 13 이후보다 중성 채도가 높아 OS 버전에 따라서도 달라진다. 강조색은 면적이 좁고 그
  자리에서 "이것이 주 동작"이라는 말만 하면 되므로 배경화면을 따라가도 잃는 것이 없다.
- 판은 두 층이다. 카드가 얹히는 바닥과 글자가 직접 놓이는 판이며, `ui/theme/TigerSurface.kt`가
  역할마다 정의한다. 카드를 담는 홈과 Task Session 목록은 바닥을 어둡게 깔고, 카드 없이 내용을
  한 덩어리로 쌓는 상세는 흰 판을 바닥으로 깐다. 띄울 카드가 없는 화면의 바닥을 어둡게 하면 화면이
  통째로 회색이 되어 아직 그려지지 않은 것처럼 보인다. iOS도 grouped list에만 회색 바닥을 준다.
- 카드는 바닥보다 밝다. 카드를 배경에서 갈라 보이게 하는 수단으로 이 방향을 고른 것이다. 전에는
  반대여서(바닥 `#F6FAFF`, 카드 `#DCE3E9`) 카드가 떠오르는 것으로 읽히지 않았다. 실측 대비는
  1.24:1이었으나 대비값이 원인은 아니다. iOS의 grouped list는 같은 짜임을 1.12:1로 만들고, 그보다
  낮은데도 카드가 떠 보인다. 사람은 빛이 위에서 온다고 보아 밝은 면을 앞으로 읽으므로, 카드가
  바닥보다 어두우면 떠오른 것이 아니라 파인 것으로 읽힌다. 방향을 뒤집으면 같은 크기의 밝기 차가
  "떠 있음"으로 읽힌다.
- 카드에 그림자나 외곽선을 주지 않는다. 밝기 방향과 카드 사이 간격이 이미 경계를 만들고, 거기에
  더하면 한 항목에 경계가 셋이 된다.
- 채움 대비 3:1을 목표로 삼지 않는다. 밝은 바닥 위 밝은 카드로는 만들 수 없고(한쪽이 중간 회색까지
  어두워져야 한다), WCAG 1.4.11은 컴포넌트를 식별하는 데 필요한 시각 정보를 요구하는 조항이라 안에
  담긴 이름과 수집 일시로 식별되는 이 카드에는 적용되지 않는다. 지켜야 하는 것은 글자 대비 AA이고
  그것은 모든 쌍에서 유지한다.
- 글자는 색을 비워 두지 않는다. 비우면 놓인 자리의 콘텐츠 색을 따라 같은 역할이 자리마다 다르게
  렌더된다. 실제로 Material 3의 Card가 콘텐츠 색으로 `onSurfaceVariant`를 주어 카드 안의 이름만
  옅어졌고, 색을 명시해 둔 식별자가 같은 카드의 제목보다 진해져 위계가 뒤집혔다. 표면 위에서 읽는
  역할은 모두 진한 잉크(`onSurface`)와 옅은 잉크(`onSurfaceVariant`) 중 하나를 골라 명시한다.
  카드 색과 그 위 콘텐츠 색을 함께 정하는 자리는 `ui/common/TigerCard.kt` 하나다.
- 글꼴은 하나만 쓴다. 식별자에도 고정폭을 쓰지 않는다. 글자 단위 대조에는 고정폭이 낫지만, 한
  화면에 글꼴이 둘이면 그 이득보다 위계를 가리는 손해가 크다. 목록의 열 정렬은 오른쪽 맞춤이
  이미 준다.
- 오른쪽 단의 값들은 한 크기로 둔다. 크기가 다르면 두 값이 한 단으로 읽히지 않는다. 같은 크기라도
  한글은 라틴 글자보다 em 상자를 꽉 채워 커 보이므로, 오른쪽에 한글이 오고 왼쪽에 라틴 글자가 오면
  행이 어긋난 것처럼 보인다. baseline은 맞춰 두어야 하지만 그것만으로는 이 어긋남이 해소되지
  않으므로 크기를 묶는다.
- 상세 본문은 이름과 정보를 띄워 두 묶음으로 가른다. 간격은 줄 사이보다 넓고 다음 묶음보다는
  좁게 둔다. 간격의 크기가 곧 묶음의 경계다.
- 세션 정보의 값은 시트 제목보다 한 단계 작다. 같은 크기이면 제목이 목록의 첫 항목처럼 읽히고 큰
  글자가 사다리처럼 쌓인다. 이름표와의 차이도 한 단계로 좁혀 두 줄이 한 묶음으로 붙게 하고, 행
  사이는 값의 크기에 맞춰 좁힌다. 전체 식별자가 한 줄에 들어가야 행 높이가 고르다.
- 크기는 셋이다. 제목 22sp, 본문 16sp, 목록 값 14sp. 다만 한 화면이 쓰는 크기는 둘이고, 그 둘은 늘
  타입 스케일에서 이웃한 칸이다. 목록은 이름(16)과 값(14), 상세는 제목(22)과 본문(16)이다. 짝이
  화면마다 다를 뿐이다.
- 한 칸을 건너뛰지 않는다. 건너뛰면 층이 갈리는 것이 아니라 위가 홀로 커 보인다. 상세가 본문 층 없이
  제목 22sp에서 값 14sp로 곧장 떨어지던 동안 그랬다. Material 3과 Apple HIG 모두 본문을 14~17에
  두는데, 그 자리가 비어 있으면 제목과 값 사이에 읽을 것이 없다.
- 상세는 목록의 밀도를 따르지 않는다. 훑는 화면이 아니라 확인하는 화면이라 줄을 아낄 이유가 없다고
  정했으면, 크기도 아낄 이유가 없다. 같은 Object 값이 카드에서 14sp, 상세에서 16sp인 것은 그래서다.
  세션 정보 시트는 훑어 확인하고 닫는 판이므로 목록 쪽을 따른다.
- 같은 층에 값이 여럿이라고 크기를 한 단계씩 더 내리지 않는다. 층이 늘어나는 것이 아니라 맨 위가
  홀로 커진다. 카드가 16·14·12로 세 칸을 쓰던 동안 이름과 가장 작은 값의 차이가 1.33배로 벌어졌다.
  값들끼리는 굵기와 잉크로 가른다. 값이 넷인 GitHub의 커밋 행도 조합 셋으로 끝내면서 글꼴은 하나,
  크기는 둘만 쓴다.
- 지금 무엇을 할 수 있는지 말하는 줄은 그 층의 진한 잉크를 쓴다. 상세의 전송 상태가 여기 해당한다.
  이름에 딸린 값이 아니라는 것은 잉크로 말하고 크기로 말하지 않는다. 한 단계 큰 조합을 그 한 줄만
  쓰던 동안, 상세에서 그 줄만 위아래와 다른 글자로 보였다.
- 지금 무엇을 할 수 있는지 말하는 줄도 값과 같은 크기다. 상세의 전송 상태가 여기 해당한다. 그것이
  이름에 딸린 값이 아니라는 것은 잉크를 옅게 두지 않는 것으로 말하고, 크기까지 올리지 않는다. 한
  단계 큰 조합을 그 한 줄만 쓰던 동안, 상세에서 그 줄만 위아래와 다른 글자로 보였다.
- 식별자는 부수 정보가 아니다. 이 앱은 배포용이 아니라 수집용이고, 서버에 올라간 수집분을 찾을 때
  쓰는 것은 수집 일시가 아니라 이 값이다. 그래서 수집 일시와 같은 행의 오른쪽 끝에 두어 훑는 눈이
  먼저 닿게 하고, 색은 옅게 하지 않으며 굵기를 한 단계 올린다. GitHub의 커밋 목록도 짧은 SHA의 색을
  본문과 같게, 굵기를 주변 작은 글자보다 한 단계 굵게 둔다.
- 전송 상태는 두 번째 행의 오른쪽 끝에 둔다. 이름에 딸린 값과 같은 역할을 쓰므로 제 조합을 갖지
  않는다. 한 행에 크기가 다른 두 글자가 놓이면 baseline을 맞춘다. 위를 맞추면 작은 글자가 큰 글자의
  윗선에 붙어 떠 보인다.
- 한글 줄이 왼쪽 더미에서 빠지는 효과도 있다. `E`나 `I`는 세로 획이 한 열을 꽉 채워 서지만 `업`의
  ㅇ은 완만한 곡선이라, 나란히 쌓으면 상자 원점이 같은데도 한글 줄만 들여쓴 것처럼 보인다.
- 상세 본문은 목록 카드의 줄 수 제한을 따르지 않는다. Material 3이 보조 줄을 1~3줄로 제한하는 것은
  훑는 목록의 규칙이고, 상세는 확인하는 화면이라 줄을 아낄 이유가 없다. 이름표와 값을 층마다 한 줄씩
  쌓는다. 세션 정보 시트가 이미 같은 형태다. Task와 Object는 같은 종류라 같은 층에 나란히 놓인다.
- 이름이 없는 쪽에는 그 자리를 세우지 않고, 둘 다 없으면 줄째로 뺀다. 비어 있는 이름표는 값이
  없다는 것보다 이름이 없는 물체라는 뜻으로 읽힌다. 이전 버전에서 Episode 없이 마감된 Session이
  여기 해당하며, 그 두 이름은 어디에도 저장된 적이 없어 되살릴 수 없다.
- 길게 눌러 여는 메뉴는 누른 지점에서 연다. 카드를 앵커로 삼으면 폭이 화면을 꽉 채우므로 어디를
  눌렀든 카드 구석에서 열려 방금 건드린 곳과 멀어진다.
- 목록이 비면 남은 공간 가운데에 안내를 둔다. 목록 항목처럼 왼쪽 위에 붙이면 곧 채워질 자리를
  기다리는 빈 행으로 읽힌다. 화면에 혼자 있는 문장이므로 카드 안 메타 정보보다 크게 둔다. 안내는
  무엇을 눌러 세션을 추가하는지 그 행동의 이름을 그대로 불러 준다.
- 프리뷰 위에 얹는 문구는 배경이 장면마다 달라지므로, 장면이 가장 밝을 때를 기준으로 명도 대비가
  WCAG AA를 넘는 색만 쓴다. 비활성 제어에 쓰는 색을 읽어야 하는 문구에 쓰지 않는다.
## 전송 동작
- 전송 상태는 Session Detail에서 보여 준다. 전용 화면을 두지 않는다.
- 아직 올리지 않은 상태는 문구로 적지 않는다. 그 상태에서만 나오는 전송 버튼이 이미 같은 말을 한다.
  전송 중·완료·실패는 각자 할 말이 있으므로 문구로 표시한다.
- 진행률을 표시하지 않는다. 서버에 진행을 묻지 않으므로 얼마나 왔는지 알 수 없다.
- 전송 중에도 Detail을 벗어날 수 있다. 둘러보는 화면에서 나가는 것을 중단 의사로 읽지 않는다.
  사용자가 전송을 중간에 끊는 수단은 두지 않는다.
- `UPLOADING`에서 앱이 백그라운드로 전환되면 어느 화면에 있든 즉시 취소하고 `FAILED`를 기록한다.
  이후 Detail에서 재전송한다.
- 실패하면 Detail에 사유와 재전송을 함께 표시한다. 사유는 저장하지 않으므로 앱을 다시 켜면 상태만
  남는다. 재전송 여부는 사용자가 사유를 보고 정하며, 사유에 따라 재전송을 감추지 않는다.
- 서버 polling이나 백그라운드 전송을 하지 않는다.
## 삭제 동작
- 삭제는 기기에서만 일어난다. 서버에 DELETE API가 없으므로 이미 업로드된 데이터는 서버에서 삭제되지
  않는다. 저장 공간을 비우는 동작이지 업로드를 취소하는 동작이 아니다.
- 진입점은 Session Detail의 상단 우측 메뉴와 Task Session 목록 카드의 길게 누르기 둘이다. 어느
  쪽에서 열든 같은 확인 판을 쓴다.
- 확인 문구는 업로드 여부로 갈린다. 아직 올리지 않은 Session은 수집한 데이터를 복구할 수 없음을,
  전송이 끝난 Session은 서버에 업로드된 데이터가 삭제되지 않음을 알린다. 두 경우를 같은 문구로
  덮으면 앞쪽에서 사용자가 무엇을 잃는지 모른 채 확인을 누른다.
- 되돌릴 수 없는 확인 판은 하나의 형태를 쓴다. 세션 종료 확인과 세션 삭제 확인이 다르게 보이지
  않는다. 확정은 채워진 error 버튼, 취소는 text 버튼이다. 글씨 색만으로는 두 선택이 같은 무게로
  보인다.
- 확인 판이 뜨는 동안 영상 재생을 멈춘다. 되돌릴 수 없는 확인을 받는데 뒤에서 소리가 계속 나면
  무엇을 묻고 있는지 흐려지고, 확인하면 재생기가 연 그 파일이 곧 사라진다. 재생기를 놓지는 않는다.
  놓으면 판 뒤의 재생 영역이 빈 화면이 되어 무엇을 덮고 있는지 알 수 없다.
- `UPLOADING` 상태에서는 삭제할 수 없다. 전송이 번들을 읽고 있는 동안 지우면 전송이 무엇을 읽는지
  알 수 없게 된다. 전송을 끊는 수단을 두지 않으므로 전송이 끝나거나 실패한 뒤에 삭제한다. 진입점은
  이때 누를 수 없는 상태로 보이며, 막힌 이유는 같은 화면의 전송 상태가 말한다.
- 색인을 먼저 지우고 번들 디렉터리를 지운다. 디렉터리 삭제가 실패해도 남는 것은 목록에 보이지 않는
  고아 디렉터리뿐이고, 다음 실행이 회수한다. 반대 순서였다면 번들이 사라진 Session이 목록에 남아
  재생도 전송도 되지 않는다.
- 고아 번들 회수는 앱 시작 시 staging 구제가 끝난 뒤에 돈다. 구제가 staging에서 옮겨 온 번들은
  색인에 행이 있으므로 고아가 아니지만, 순서를 뒤집으면 옮겨지기 전 상태를 보고 판단하게 된다.
- 삭제한 Session은 중단된 수집의 구제 경로로 되살아나지 않는다. 구제는 색인에 행이 있는 Session만
  대상으로 한다.
- 삭제는 이 저장소가 관리하는 completed 번들에만 미친다. 이전 버전의 외부 저장소 경로는 건드리지
  않는다.
- Session Detail에서 삭제하면 그 화면은 가리킬 대상이 없어지므로 직전 화면으로 돌아간다. 목록에서
  삭제하면 목록에 머무르고 그 카드만 사라진다.
