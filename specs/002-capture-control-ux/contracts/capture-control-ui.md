# Capture Control UI 계약

## 화면과 진입점

| 화면 | 진입 | 주요 행동 | 이탈 동작 |
| --- | --- | --- | --- |
| Session 목록 | 앱 시작, Detail 복귀 | 관리되는 완료 Session 열기, 새 수집 시작 | 일반 화면 전환 |
| 수집 작업 공간 | 새 수집 | 라이브 프리뷰 준비, 공통 task/object 입력, 재생·일시 정지·정지 | 뒤로 가기·닫기는 수집 종료 확인 필요 |
| Session Detail | 목록에서 완료 Session 선택 | 전송 또는 재전송 시작 | 목록으로 복귀 |
| 업로드 상태 화면 | 정지가 확정·업로드 시작, Detail이 전송·재전송 시작 | 비결정적 진행과 종료 상태 확인 | 업로드 중 뒤로 가기·닫기는 취소 확인 필요 |

## 수집 제어

| 상태 | 활성 제어 | 이벤트 |
| --- | --- | --- |
| 유효한 task/object가 입력된 준비 상태 | 재생 | Session과 첫 Episode 생성 |
| Episode 진행 중 | 일시 정지, 정지 | 일시 정지는 Episode 완료, 정지는 Episode 완료·Session 확정·업로드 시작 |
| Episode 없음, Session 수집 중 | 재생, 정지 | 재생은 다음 Episode 시작, 정지는 확정·업로드 시작 |
| 확정 중 | 없음 | 업로드 상태 화면 준비가 끝날 때까지 중복 제어 무시 |

제어 아이콘에는 접근성 라벨과 툴팁을 제공한다. task와 object는 주 수집 제어가 아닌 준비 입력이다.

첫 재생 전에는 권한·AR·camera 준비로 라이브 프리뷰만 실행한다. 프리뷰 실패 시 다음 행동을 안내하고 재생을 막으며, Session이나 원시 bundle을 만들면 안 된다.

## 업로드 상태 동작

- 기존 업로드 요청이 성공 또는 실패할 때까지 비결정적 진행 표시를 보여 준다.
- 전송 중에는 화면 이탈이 전송을 중단한다는 문구를 계속 표시한다.
- `UPLOADING`에서 뒤로 가기·닫기를 누르면 계속 또는 중단을 묻는다. 중단 확인 시 활성 작업을 취소하고 `FAILED`를 기록한다.
- `UPLOADING`에서 앱이 백그라운드로 전환되면 확인 없이 즉시 취소하고 `FAILED`를 기록한다. 이후 Detail에서 재전송한다.
- 서버 polling이나 백그라운드 전송을 하지 않는다.
